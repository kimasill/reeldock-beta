# ReelDock Beta

**게임에 집중하고, 원하는 순간을 로컬에 남기세요.**

Windows 게임·화면·방송 녹화를 위한 무료 알파입니다. 네이티브 UI로 별도 OBS Studio 엔진을 제어합니다. 녹화, 일시정지, 최근 장면 저장, 출력 상태 확인을 한곳에 모았습니다.

**[Windows x64 알파 다운로드](https://github.com/kimasill/reeldock-beta/releases)** · **[첫 사용 결과 / 오류 제보](https://github.com/kimasill/reeldock-beta/issues/new/choose)**

## 3단계로 시작

1. ZIP을 풀고 `ReelDock.exe`를 실행한 뒤 **엔진 준비 · 연결**을 누릅니다. .NET은 포함되어 있습니다. 첫 설치에는 공식 OBS 32.2.2 다운로드 약 180 MB와 인터넷이 필요합니다.
2. 게임·디스플레이·창을 고르고 장면 확인으로 캡처를 확인합니다. GPU 인코더와 프로필을 적용하고 원하는 소리만 켭니다.
3. 녹화 시작. `Ctrl+Shift+F9`로 종료하면 MKV 파일이 적용한 녹화 폴더에 저장됩니다. 리플레이 버퍼를 켠 뒤 `Ctrl+Shift+F8`로 최근 장면을 저장할 수 있습니다.

## 지금 되는 것

- NVENC·AMF·QSV H.264 선택과 CPU x264 대안
- MKV 녹화·일시정지·리플레이와 전역 단축키
- 프로필 적용 시 일반 녹화 파일 덮어쓰기 비활성화; 새 출력 전 안전한 설정인지 확인
- 실제 녹화 시작 확인, 관측한 예상 밖 종료 경고, 상태 변경 시 버튼 의도 보호
- 느린 녹화·리플레이 중지 확인에 합산 제한시간 적용; 실패 시 미확인 상태와 저장 경고 표시
- 명시적인 명령을 누르면 배경 상태 조회 대기를 먼저 중단하여 중지·리플레이 저장 요청의 불필요한 대기 축소
- 리플레이 저장마다 고유 파일명을 준비하고 요청과 일치하는 경로 알림만 확인; 결과 미확인 중 중복 저장·버퍼 중지·엔진 종료 보호
- 앱 종료 확인 중 새 명령·중복 종료 차단, 활성·미확인 출력에서는 확인 후 제어 앱만 닫기
- 페이지를 바꿔도 유지되는 녹화 제어, 좁은 창에 맞춘 배치와 고정 방송 상태 표시
- 외부 상태 변경 시 녹화·방송·리플레이·일시정지가 반대 동작을 실행하지 않도록 확인
- ReelDock 시스템 소리·마이크 입력의 종류·고유 식별자를 확인한 음소거 표시; 같은 이름의 다른 입력으로 명령 전환 방지
- 새 출력 확인창에 설정된 오디오 장치 표시; OBS에서 장치가 바뀌면 이전 확인 재사용 방지
- 음소거 해제된 입력이 현재 출력에서 비활성이면 경고하고 새 출력 시작 차단
- 출력 중 같은 작업 공간에 재연결, 설정 불일치 검사
- 고급 출력에서도 녹화 폴더 설정을 독립 조회; 미확인 폴더의 이전 목록·선택 제거
- 클립 재생·다른 앱으로 열기·탐색기 선택·경로 복사
- OBS 성능 수치와 CSV, 최신 장면 식별자를 전후 확인한 단일 스냅샷

방송 플랫폼 연결·MP4 리먹스·고급 오디오 설정은 OBS에서 설정합니다. 앱의 방송 시작 버튼은 설정된 목적지를 확인한 뒤 사용합니다. Stream Deck에서 위 키 조합을 Hotkey로 지정할 수 있지만, 전용 플러그인이나 실제 하드웨어 검증은 아직 없습니다.

앱을 닫으면 녹화·방송·리플레이·가상 카메라 상태를 새로 확인합니다. 실행 중이거나 확인할 수 없으면 제어 앱만 닫을지 묻고 OBS는 유지합니다. 취소하면 제어 버튼을 다시 사용할 수 있습니다. 이미 진행 중인 중지·저장 작업은 닫기 요청으로 취소하지 않습니다. 네 가지 출력 조회에는 합산 3초 제한이 있지만, 기존 통신 정리와 창 닫기까지 포함한 전체 종료 시간 제한은 아닙니다.

일반 녹화의 파일 덮어쓰기 방지 설정이 꺼져 있거나 확인되지 않는다는 안내가 나오면, 진행 중인 출력을 직접 중지한 뒤 **프로필 적용**을 누르세요. 녹화·방송·리플레이 중지 버튼은 계속 사용할 수 있습니다. 프로필 적용 시 OBS의 일반 녹화 덮어쓰기 옵션을 끄며, 새 출력을 시작하기 전에 다시 읽어 확인합니다. 마지막 검사 이후 외부에서 설정을 바꾸는 경우까지 막는 기능은 아닙니다.

리플레이 저장은 매 요청마다 고유 식별자와 시각이 들어간 파일명을 준비합니다. 현재 출력과 저장 설정을 다시 확인한 뒤 저장을 요청하며, 준비 실패 시 저장 명령을 보내지 않습니다. 현재는 드라이브 문자로 지정한 폴더의 MKV만 지원합니다. 준비에는 합산 3초 제한이 있으며 저장 완료 시간 보장은 아닙니다. 변경한 이름 형식은 현재 출력에 남습니다. 이후 OBS에서 직접 저장하면 같은 식별자에 시각만 바뀌므로, 같은 초의 외부 저장이나 다른 제어 앱의 설정 변경·동시 저장까지 보호하지는 못합니다. 중요한 클립은 별도 사본도 보관하세요.

리플레이 저장 요청의 응답만으로 파일 저장이 완료된 것은 아닙니다. 리플레이 카드의 저장 경로 알림을 기다리고 파일을 재생해 확인하세요. 결과가 미확인이면 같은 저장을 반복 전송하지 않으며, 버퍼 중지 전 경고하고 앱 종료 시 OBS를 유지합니다. 같은 포트 재연결에도 보호가 유지됩니다. 알림이 오지 않으면 OBS와 최근 파일을 직접 확인한 뒤 **저장 결과 직접 확인 후 해제…**를 사용할 수 있습니다. 해제는 파일 검증이 아니며, 버퍼 중지에 동의해 중지가 확인된 경우에도 이전 저장 결과는 미확인으로 남습니다. 녹화·방송 중지는 계속 사용할 수 있습니다. 이 보호는 현재 앱 세션에서만 유지되며 앱 재시작 후 복구되지 않습니다. 저장 이벤트 자체에는 요청 식별자가 없지만, 대기 중에는 이번에 준비한 폴더·고유 파일명·확장자가 일치하는 알림만 확인합니다. 다른 경로가 오면 보호를 유지합니다. 경로 일치는 파일 내용이나 영구 저장의 검증이 아닙니다.

오디오를 바꾸기 전에 마지막으로 표시한 입력의 종류와 고유 식별자를 확인합니다. 그동안 입력이 교체됐거나 식별자를 확인할 수 없으면 변경 명령을 보내지 않습니다. 이때 상태를 다시 확인하고 OBS에서 해당 입력을 확인하세요. 상태 조회 전후에 동일한 입력인지 확인하며, 연결이 끊긴 뒤 늦게 도착한 응답은 표시하지 않습니다. 오디오 조회에는 합산 2초, 변경과 결과 확인에는 합산 3초 제한이 있습니다. 실패한 변경을 자동으로 반복하지 않으며, 이후 조회가 현재 상태를 복구해도 이전 변경의 성공을 뜻하지는 않습니다. 녹화·방송·리플레이 중지는 계속 사용할 수 있습니다. 고유 식별자를 제공하지 않는 구형 외부 엔진은 오디오 제어를 미확인으로 표시합니다.

오디오 체크 표시는 음소거 해제 상태입니다. 비활성·경로 확인 불가 경고가 나오면 OBS에서 입력이 현재 장면에 연결돼 있는지 확인하세요. 경로가 활성이어도 실제 소리, 장치 상태, 음량과 트랙 설정까지 보장하지는 않습니다. 첫 테스트 녹화는 직접 재생해 확인하세요.

시작 확인창의 장치 이름은 OBS에 설정된 장치입니다. “Windows 기본 통신 입력”은 기본 마이크의 물리 장치를 특정한 것이 아니며 Windows 설정에 따라 바뀔 수 있습니다. “설정된 오디오 장치 확인 불가”가 나오면 OBS에서 해당 장치를 다시 선택하세요. 이미 진행 중인 출력 중지는 계속 사용할 수 있습니다.

녹화 종료·시작 확인 경고가 나오면 OBS 상태와 최근 파일의 재생 여부를 확인하세요. 알림 닫기는 파일 검증이 아닙니다. 장면 확인은 표시된 장면·시각의 단일 스냅샷이며 이후 변경과 전환 효과는 반영하지 않습니다. 대상 설명은 OBS에 저장된 게임 모드·창 이름입니다. 디스플레이 이름은 이번 연결에서 선택한 입력과 값이 일치할 때만 선택 당시 이름으로 표시합니다. 이름을 확인하지 못하면 화면 버튼에서 다시 선택하세요. 설정 정보는 실제 연결된 게임이나 화면 수신을 보장하지 않습니다. 조회 실패·입력 변경 시 이전 표시와 시작 확인을 지우며 기존 출력 중지는 유지합니다.

“출력 상태가 변경되어 동작하지 않았습니다”는 OBS에서 바뀐 상태가 버튼 표시와 달라 명령을 보내지 않았다는 뜻입니다. 갱신된 상태를 보고 원하는 동작을 다시 선택하세요. “상태 다시 확인” 버튼은 상태만 읽으며 출력을 시작하거나 중지하지 않습니다.

녹화·리플레이 중지 요청과 종료 확인에는 합산 15초 제한이 적용됩니다. 요청별 제한으로 더 일찍 실패할 수 있으며, 사전 조회와 일반 상태 갱신 시간은 별도입니다. 종료 확인 실패가 나오면 OBS에서 실제 출력 상태를 확인하세요. 녹화 파일은 직접 재생해 확인해야 합니다. 리플레이 중지는 클립 저장이 아니므로, 필요한 장면은 중지 전에 저장하세요.

중지·최근 장면 저장 같은 명령은 배경 조회의 응답 대기를 먼저 중단합니다. 클릭 당시 동작과 현재 출력 상태가 다르면 기존처럼 명령을 보내지 않습니다. 이미 보낸 명령은 중단하지 않으며, 엔진 송신이나 명령 자체의 응답이 막힌 경우에는 여전히 기다릴 수 있습니다. 모든 상황에서 즉시 중지하거나 원하는 리플레이 구간을 보존한다는 보장은 아닙니다.

클립 라이브러리는 **마지막으로 조회한 OBS 녹화 폴더 설정**을 표시합니다. 연결·프로필 적용·라이브러리 열기·새로고침 때 조회하며, 설정 화면에서 편집 중인 폴더와 구분합니다. 고급 출력의 설정 복구가 지원되지 않아도 파일 출력 폴더는 따로 조회합니다. 연결 해제·조회 실패·설정 변경이 감지되면 이전 목록과 선택을 지웁니다. 연결하지 않은 상태에서는 저장된 환경설정의 폴더를 현재 폴더로 대신 표시하지 않습니다. 다시 연결하고 새로고침하세요.

파일 목록은 별도 작업에서 읽어 녹화 제어를 계속 사용할 수 있게 했습니다. 목록의 읽는 중·빈 폴더·오류 안내는 라이브러리에 따로 표시합니다. 새로고침을 반복하면 이전 결과를 버리고 최신 요청만 대기시킵니다. 목록은 최대100개이며, 조회 당시의 이름·수정시각·크기입니다. 녹화 중 크기 변경이나 삭제·이동을 즉시 반영하지는 않습니다. 종료 확인은 목록 읽기가 끝날 때까지 기다리지 않으며, 닫기를 취소한 뒤에는 필요하면 목록을 새로고침하세요.

취소는 진행 중인 운영체제 파일 조회를 강제로 끝내지 않습니다. 디스크가 응답하지 않으면 다음 목록 조회가 기다릴 수 있습니다. 비동기 조회도 디스크·CPU 자원을 사용하며 게임 성능 개선을 보장하지 않습니다.

폴더 조회에는 합산 2초 제한이 있습니다. 이후 파일 목록을 읽는 시간은 별도이며, 드라이브 문자 경로만 지원합니다. FFmpeg 네트워크 출력·UNC 경로는 표시하지 않습니다. 폴더가 없거나 접근할 수 없는 상태와 파일이 없는 상태를 구분하며 폴더를 자동 생성하지 않습니다. 목록은 해당 폴더의 MKV·MP4·MOV 파일 최대 100개입니다. 현재 녹화나 리플레이가 실제로 그 위치에 저장됐다는 보장은 아니므로, 저장 완료와 재생 여부는 직접 확인하세요.

## 알파의 현재 한계

alpha.16은 무표시 WPF·모의 WebSocket154그룹, 생성 파일 목록13그룹, 오프스크린 배치20개를 통과했습니다. 모의 파일 조회를 보류한 상태에서도 제어 요청이 전달되는 것을 확인했습니다. 실제 느린 디스크·OBS 중지 완료·게임 성능·사용자 경험 검증은 별도입니다. 생성 파일로 최신100개 선택·취소·오류 처리를 검사했습니다.

alpha.15의 폴더 조회·연결 상태 복구와 기존 제어는 무표시 WPF·모의 WebSocket 143그룹을 통과했습니다. 이전 앱에서 고급 출력의 오래된 폴더 표시와 늦은 응답의 상태 복구 문제 3건을 재현했습니다. 새 검증은 실제 OBS·파일 녹화·사용자 평가가 아니며, 테스트 폴더의 작은 비미디어 파일만 사용했습니다.

alpha.14의 오디오 입력 식별·변경과 기존 제어 동작은 무표시 WPF·모의 WebSocket 126그룹으로 검사했습니다. 같은 이름의 입력 교체, 잘못된 응답, 시간 초과, 연결 해제 뒤 늦은 응답과 기존 출력 중지 보존을 확인했습니다. 실제 오디오 장치·소리·녹음 트랙이나 네이티브 UI 검증은 아닙니다.

앞선 alpha.13의 파일명 준비·이벤트 대응·기존 제어는 무표시 WPF·모의 WebSocket 111그룹, 이름 준비 12그룹으로 검사했습니다. 별도 격리 NVENC 엔진에서 생성 색상과 무음 오디오만 사용해 고정 이름 덮어쓰기를 재현하고, 고유 이름 두 개와 첫 파일 해시 보존을 확인했습니다. 보관한 파일 4개는 전체 디코딩과 정해 둔 길이·타임스탬프 허용 기준을 통과했습니다. 프레임 간격은 최대 50ms가 관측되어 무손실·완전한 프레임 보존을 뜻하지 않습니다. 이 네이티브 시험은 앱의 실제 WebSocket·Dispatcher·확인창을 거친 통합 검증이 아닙니다. 실제 게임 성능, AMD/Intel 실행, 장시간 녹화, 장치 오류 복구, 실제 외부 방송은 추가 검증이 필요합니다. **OBS보다 빠르다는 주장은 아직 하지 않습니다.** 실제 사용자 평가는 진행 전입니다.

Windows x64 전용이며 실행 파일에는 코드 서명이 없습니다. 코드 서명·깨끗한 PC 설치·장시간 안정성 검증을 유료 출시 전에 진행할 예정입니다. 테스트할 때 중요한 녹화의 유일한 사본을 맡기지 마세요.

## 가격과 프로젝트

현재 무료 알파이며 판매·결제를 받지 않습니다. Pro 기능과 가격은 검증 중입니다. 소스 저장소는 비공개이며, 이 저장소는 공식 바이너리 배포와 공개 피드백용입니다. 녹화물에 대한 권리는 사용자에게 있습니다. 바이너리 사용 조건과 서드파티 고지는 각 ZIP에 포함돼 있습니다.
